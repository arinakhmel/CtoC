# ІНСТРУКЦІЇ
1. Прочитай README та виділи всі згадки про користувачів: явні (ролі, аудиторія) і неявні (для кого призначений функціонал).
2. Визнач, скільки об'єктивно різних сегментів або ролей має продукт. Розділяй їх лише тоді, коли їхні цілі, поведінка та контекст суттєво відрізняються. Не створюй профілі «для кількості». Обґрунтуй, чому саме стільки профілів (1 або більше).
3. Для кожного профілю опиши:
   - Назву та коротку характеристику сегмента.
   - Демографію та контекст (вік, етап навчання, регіон, спеціальність, досвід роботи), лише в межах того, що випливає з README або чітко позначеного припущення.
   - Цілі та мотивацію: що людина хоче досягти за допомогою платформи.
   - Поточні альтернативи: як вони вирішують задачу сьогодні (соцмережі, знайомі, Telegram-чати, інші біржі).
   - Ключові сценарії використання (2–4 типові ситуації).
   - Очікування від платформи та критерії довіри.
   - Ризики відмови: за яких умов користувач піде або не зареєструється.
4. Опиши взаємозв'язок між профілями: хто кому потрібен, де виникає конфлікт інтересів, який сегмент критичніший для запуску.
5. Для кожного профілю познач рівень достовірності даних: «з README» / «логічний висновок» / «припущення, що потребує перевірки».
6. Запропонуй, як верифікувати кожен профіль: конкретні запитання для інтерв'ю та дешеві методи дослідження.
7. Якщо в README недостатньо даних, прямо вкажи, чого бракує, і не вигадуй факти.

# ФОРМАТ ВИВОДУ
Звіт українською мовою з такими розділами:
1. Підсумок: скільки профілів виділено і чому (2–4 речення)
2. Профілі користувачів (для кожного окремий блок із полями з пункту 3 інструкцій, у вигляді структурованого списку або таблиці)
3. Порівняльна таблиця профілів (параметри: цілі | поточні альтернативи | що для них критично | ключовий ризик відмови)
4. Взаємозв'язок сегментів і пріоритет для запуску
5. Реєстр припущень (припущення | рівень достовірності | як перевірити)
6. План верифікації: 8–10 запитань для інтерв'ю окремо для кожного профілю
7. Інформація, якої бракує в README
